
==========================
Jotai導入・グローバルステート設定メモ
==========================

このメモでは、ReactアプリにJotaiを導入し、複数のコンポーネントで状態を共有する方法を説明します。
ここに記載するフォルダ名やURLは例です。実際に使うプロジェクトの構成に合わせて読み替えてください。

----------------------
1. グローバルステートとは
----------------------

Reactのstateは、通常そのstateを作成したコンポーネントで管理します。
その値を離れたコンポーネントでも使いたい場合、親から子へpropsで渡す方法があります。

共有するコンポーネントが増えると、
値を使わない中間コンポーネントにもpropsを渡す必要が出ることがあります。

このように、値を複数の画面やコンポーネントで共有する状態を、
グローバルステートと呼びます。

Jotaiでは、共有する状態をAtomという小さな単位で定義します。
Atomを利用するコンポーネントは、そのAtomの値を読み取ったり、
更新したりできます。

----------------------------
2. Jotaiを使う目的とメリット
----------------------------

Jotaiを使うと、共有したい値をコンポーネントの外にAtomとして定義できます。
値をpropsで何段も受け渡さなくても、必要なコンポーネントから同じAtomを利用できます。

主なメリット:

・状態を小さなAtomごとに分けて管理できる
・状態を使うコンポーネントがAtomを直接読み書きでき、propsの受け渡しを減らせる
・状態の読み取りだけを行うコンポーネントと、更新も行うコンポーネントを分けやすい
・Reactのコンポーネント構成に沿って状態を扱える

向いている例:

・ログイン中のユーザー情報
・複数の画面で共有する選択中の項目
・画面表示の設定や、複数コンポーネントで使う入力途中の値

小さなコンポーネント内だけで使う値は、React標準のuseStateで十分な場合があります。
サーバーから取得するデータのキャッシュや再取得をまとめて管理したい場合は、
Jotaiだけで実装するより、React Queryなどのデータ取得用ライブラリが適することもあります。
共有が必要な状態に絞ってJotaiを使うと、管理が複雑になりにくくなります。

------------------------------
3. Reactアプリのフォルダを確認する
------------------------------

Jotaiのインストールは、Reactアプリのpackage.jsonがあるフォルダで行います。
このフォルダを、ここではReactアプリのルートフォルダと呼びます。

例:

sample-project/
	package.json       Reactアプリのルートフォルダ
	src/               Reactのソースコード

Reactアプリのルートフォルダで実行するコマンドの例:

cd "<Reactアプリのルートフォルダへのパス>"

<Reactアプリのルートフォルダへのパス>は、使用するプロジェクトに合わせて置き換えます。
すでにそのフォルダでターミナルを開いている場合は、cdコマンドは不要です。

----------------------
4. Jotaiをインストールする
----------------------

Reactアプリのルートフォルダで実行するコマンド:

npm install jotai

何をしているか:
JotaiをReactアプリの依存ライブラリとしてインストールしています。

インストールすると、主に次のファイルが更新されます:

package.json
アプリが使用するライブラリとしてJotaiが記録されます。

package-lock.json
インストールするライブラリの具体的なバージョンが記録されます。

node_modules/
Jotaiのライブラリ本体が保存されます。

すでにpackage.jsonにjotaiが登録されている場合は、改めて追加インストールする必要はありません。
別のPCなどで環境を準備する場合は、package.jsonとpackage-lock.jsonがあるフォルダで
npm installを実行すると、登録済みのライブラリをまとめてインストールできます。

------------------------------------
5. Atomを定義するファイルを作成する
------------------------------------

状態を定義するファイルは、機能ごとに管理しやすい場所へ作成します。
例えば、ユーザー状態なら次のような配置にできます:

src/
	modules/
		auth/
			current-user.state.ts

配置場所やファイル名に決まりはありません。
チームやプロジェクトで既存のフォルダ構成がある場合は、それに合わせてください。

Atomの例:

import { atom } from 'jotai';

type User = {
	id: string;
	name: string;
	email: string;
};

export const currentUserAtom = atom<User | undefined>(undefined);

何をしているか:
atom関数で、User型の値を保存するAtomを作成しています。
初期値をundefinedにしているため、最初はユーザーが設定されていない状態です。
exportを付けると、別のファイルからこのAtomをimportして利用できます。

プロジェクト内にUser型がすでにある場合は、新しい型を重複して作らず既存の型をimportします。
状態の型や初期値は、実際に共有したいデータに合わせて変更します。

-------------------------------
6. コンポーネントでAtomを使う
-------------------------------

値を読み取り、同時に更新もする場合はuseAtomを使います:

import { useAtom } from 'jotai';
import { currentUserAtom } from './current-user.state';

const [currentUser, setCurrentUser] = useAtom(currentUserAtom);

currentUserには現在の値が入り、setCurrentUserは値を更新する関数です。
更新すると、そのAtomを利用しているコンポーネントが新しい値で再描画されます。

値を読み取るだけの場合はuseAtomValueを使います:

import { useAtomValue } from 'jotai';

const currentUser = useAtomValue(currentUserAtom);

値を書き込むだけの場合はuseSetAtomを使います:

import { useSetAtom } from 'jotai';

const setCurrentUser = useSetAtom(currentUserAtom);

目的に合ったフックを使うと、そのコンポーネントが読み取りと更新のどちらを行うのか分かりやすくなります。

--------------------------------
7. 簡単なカウンターの使用例
--------------------------------

Atomを定義するファイル:

import { atom } from 'jotai';

export const countAtom = atom(0);

値を表示・更新するReactコンポーネント:

import { useAtom } from 'jotai';
import { countAtom } from './count.state';

function Counter() {
	const [count, setCount] = useAtom(countAtom);

	return (
		<button onClick={() => setCount(count + 1)}>
			{count}
		</button>
	);
}

Atomを使うコンポーネントが複数あっても、同じcountAtomを読み書きすれば同じ値を共有します。
実際のimportパスは、Atomファイルとコンポーネントの配置に合わせて変更してください。

-------------------------------
8. Providerについて
-------------------------------

基本的なJotaiの使い方では、必ずしもProviderを追加する必要はありません。
Providerを使わない場合、同じアプリ内のコンポーネントはJotaiの既定ストアを共有します。

Providerは、特定のReactツリーに専用の状態ストアを用意したい場合などに使います。
Providerで囲んだ範囲ごとに別の状態を持たせたい場合や、テストで状態を分離したい場合に利用できます。
必要がないのにProviderを追加するのではなく、アプリの要件に合わせて選びます。

------------------------------
9. 状態管理で注意すること
------------------------------

Atomの値は、通常メモリ上で管理されます。
ブラウザを再読み込みすると初期値に戻るため、ログイン状態などを再読み込み後も保持するには、
サーバーとの再認証や安全な保存方法などを別途設計する必要があります。
Jotaiを導入しただけで、データがデータベースやブラウザに自動保存されるわけではありません。

パスワードや秘密鍵などの機密情報を、共有しやすいからという理由だけでAtomに長期間保存しないでください。
どの情報を共有する必要があるかを決めてからAtomを作成します。

----------------------------
10. このプロジェクトでの実装例
----------------------------

この節は現在のプロジェクトにおける実例です。
別のプロジェクトで導入するときは、各自のファイル名や画面構成に読み替えてください。

src/modules/auth/current-user.state.ts
User型のユーザー情報を保持するcurrentUserAtomを定義しています。
初期値は未設定です。

src/modules/users/user.entity.ts
ユーザー情報の型を定義しています。id、email、nameを持ち、パスワードは含めていません。

src/pages/Signin/index.tsx
ログインAPIが成功したとき、useAtomでcurrentUserAtomを更新しています。

src/pages/Signup/index.tsx
ユーザー登録APIが成功したとき、同じcurrentUserAtomを更新しています。

src/pages/Chat/index.tsx
useAtomValueでユーザー情報を読み取ります。未ログインの場合はサインイン画面へ移動します。

src/modules/auth/auth.repository.ts
バックエンドへログイン・登録リクエストを送り、ユーザー情報とトークンを受け取ります。
現在の実装では、ユーザー情報はcurrentUserAtomへ保存しますが、トークンはAtomには保存していません。

package.json
jotaiなど、Reactアプリが使用するライブラリを管理します。

この例では、サインインやサインアップに成功したユーザー情報を複数の画面で共有しています。
トークンの保存方法や、ブラウザ再読み込み後のログイン維持は別の設計事項です。

----------------------
全体の流れ（まとめ）
----------------------

Reactアプリのルートフォルダで実行:

npm install jotai

状態を共有するファイルでAtomを定義し、必要なReactコンポーネントから利用:

atom()で状態を定義
useAtomで読み取りと更新
useAtomValueで読み取りのみ
useSetAtomで更新のみ

Jotaiは、Reactアプリ内で共有したい状態を管理するライブラリです。
導入後、共有する値をAtomとして定義し、その値を必要とするコンポーネントで利用します。
