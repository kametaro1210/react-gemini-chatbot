
==========================
Axios導入・環境変数設定メモ
==========================

このメモでは、ReactアプリにAxiosを導入し、.envファイルを使ってAPIの接続先を設定する方法を説明します。
Axiosは、ブラウザで動作するReactアプリからバックエンドへHTTPリクエストを送るためのライブラリです。

ここに書かれているコマンドはnpmを使う場合の例です。
別のパッケージマネージャーを使っているプロジェクトでは、そのプロジェクトで使われている方法に読み替えてください。

Reactアプリのルートフォルダとは、Reactアプリのpackage.jsonが置かれているフォルダです。
.envファイルも、基本的にこのフォルダに作成します。
ソースコードが入っているsrcフォルダや、バックエンドのフォルダとは異なる場合があります。

------------------------------------
1. Reactアプリのフォルダへ移動する
------------------------------------

Reactアプリのフォルダがある場所から実行するコマンドの例:

cd "<Reactアプリのフォルダへのパス>"

何をしているか:
Reactアプリのpackage.jsonがあるフォルダへ移動しています。

なぜ必要か:
npm installなどのnpmコマンドは、現在いるフォルダのpackage.jsonを使います。
別のアプリのフォルダや親フォルダで実行すると、Reactアプリとは別の依存関係に対して操作することがあります。

<Reactアプリのフォルダへのパス>は、実際に使用するフォルダのパスに置き換えます。
例えば、package.jsonがC:\projects\sample-appにある場合は、次のように移動します:

cd "C:\projects\sample-app"

package.jsonがあるフォルダであることを確認してからnpmコマンドを実行してください。

----------------------------
2. Axiosをインストールする
----------------------------

Reactアプリのフォルダで実行するコマンド:

npm install axios

何をしているか:
AxiosをReactアプリの依存ライブラリとしてインストールしています。

インストール後に更新される主なもの:

package.json
使用するライブラリとバージョンの範囲を記録します。

package-lock.json
実際にインストールする依存関係のバージョンを記録します。

node_modules/
インストールされたライブラリ本体が保存されます。

package.jsonのdependenciesにaxiosがすでにある場合は、改めて追加インストールする必要はありません。
別の環境で依存ライブラリを入れる場合は、
package.jsonとロックファイルがあるReactアプリのフォルダで次を実行します:

npm install

npm installは、package.jsonとpackage-lock.jsonをもとに必要なライブラリをインストールします。

-----------------------------
3. .envファイルを作成する
-----------------------------

作成する場所:

<Reactアプリのルートフォルダ>\.env

何をしているか:
Reactアプリが参照する環境ごとの設定値を記述するファイルです。
例えば、APIサーバーの接続先URLを設定できます。

.envの記述例:

VITE_API_URL=http://localhost:8000

これはローカル開発用の例です。localhostは自分のパソコンを表し、8000は接続先サーバーのポート番号です。
ポート番号とURLは、使用するAPIサーバーの設定に合わせて変更してください。
実際にリクエストを送るには、そのURLでAPIサーバーが起動している必要があります。

環境変数の名前について:
VITE_API_URLという名前は、Viteを使う場合の例です。
Viteでは、ブラウザ側のコードから読み込む環境変数にVITE_という接頭辞が必要です。
Create React AppやNext.jsなど、別のツールを使う場合は接頭辞や読み込み方法が異なります。
必ずそのプロジェクトで使っているツールの説明を確認し、名前とコードを合わせてください。

注意点:
.envはReactアプリのpackage.jsonと同じフォルダに作成します。
モノレポなど複数のアプリがある場合は、どのアプリが.envを読み込むかを確認してください。
フロントエンド用とバックエンド用に別の.envファイルが必要な構成もあります。

-------------------------------
4. .envをGitに登録しない
-------------------------------

プロジェクトの.gitignoreに.envが記述されていることを確認します。
.gitignoreに設定があれば、通常.envはGitの変更一覧に表示されず、リモートリポジトリにも送信されません。
設定がなければ、必要に応じて.gitignoreに.envを追加してください。

なぜGitに登録しないか:
.envには接続先やAPIキーなど、環境ごとに異なる設定を書くことがあります。
特に秘密情報をGitHubなどへ公開すると、第三者に悪用される危険があります。

重要:
フロントエンド用の環境変数は、ビルド後にブラウザから確認できる場合があります。
ViteのVITE_で始まる値も利用者に見える情報として扱います。
接続先URLなど公開してよい値は設定できますが、パスワード、秘密鍵、非公開のAPIキーなどを
フロントエンド用の環境変数に入れてはいけません。秘密情報はバックエンド側で管理します。

他の人に必要な設定項目を伝える場合は、実際の秘密値を含めない.env.exampleを用意します。
.env.exampleの例:

VITE_API_URL=http://localhost:8000

実際の.envと.env.exampleを混同しないようにしてください。

-------------------------------------------
5. Reactコードから環境変数を読み込む
-------------------------------------------

Viteを使うReactのTypeScriptファイルでは、次のように読み込みます:

const apiBaseUrl = import.meta.env.VITE_API_URL;

何をしているか:
Viteが.envから読み込んだVITE_API_URLの値を取得しています。
この例ではapiBaseUrlにhttp://localhost:8000が入ります。
Vite以外のツールでは、import.meta.env.VITE_API_URLをそのまま使えるとは限りません。
使用するツールの環境変数の読み込み方を確認してください。

------------------------------------
6. AxiosでAPIへリクエストする例
------------------------------------

Viteを使う場合のAxios利用例:

import axios from 'axios';

const apiBaseUrl = import.meta.env.VITE_API_URL;
const response = await axios.get(`${apiBaseUrl}/api/example`);
console.log(response.data);

何をしているか:
axios.getは、指定したURLにGETリクエストを送ります。
responseにはサーバーからの応答が入り、response.dataに応答データが入ります。

/api/exampleは説明用の例です。実際に使うときは、利用するAPIサーバーに実装されているURLに置き換えます。
この例はAxiosのインストールだけでは自動で実行されません。Reactのコンポーネントや関数など、
必要な場所にコードとして記述して初めてリクエストが送られます。

GET以外にも、データ送信に使うPOSTなどのリクエストがあります。
どの種類を使うか、どのURLへ送るかはAPIサーバーの仕様に合わせます。

----------------------------
7. .envを変更した後の再起動
----------------------------

.envを作成または変更した場合は、フロントエンドの開発サーバーを再起動します。
すでに起動しているターミナルでCtrl+Cを押して停止し、Reactアプリのフォルダで実行します:

npm run dev

何をしているか:
package.jsonのscriptsに定義されたdevコマンドを実行しています。
Viteを使うプロジェクトでは通常、Viteの開発サーバーが起動します。
起動後、ターミナルに表示されたURLをブラウザで開くとReactアプリを確認できます。
devコマンドが異なるプロジェクトでは、package.jsonのscriptsを確認してください。

APIへの通信を試す場合は、APIサーバーも別のターミナルで起動します。
バックエンドの起動方法は、バックエンド側のREADMEやpackage.jsonなどで確認してください。
フロントエンドとバックエンドが別々のフォルダにある場合、起動コマンドを実行する場所も異なります。

npm run devがエラーで終了した場合は、ターミナルに表示されたエラーを確認します。
開発サーバーが起動していないと、ブラウザからAPIへ接続できません。

--------------------------
8. 設定値を確認する方法
--------------------------

一時的な確認例:

console.log(import.meta.env.VITE_API_URL);

ブラウザの開発者ツールに、設定したAPIのURLが表示されれば環境変数を読み込めています。
確認が終わったら、不要なconsole.logは削除します。

環境変数を読み込めていても、APIリクエストが成功するとは限りません。
APIサーバーが起動していること、リクエスト先のURLが存在すること、サーバー側でブラウザからの接続が
許可されていること（CORS）も確認します。

----------------------
全体の流れ（まとめ）
----------------------

フロントエンドの準備（Reactアプリのルートフォルダで実行）:

npm install axios
（すでにaxiosがdependenciesにある場合は不要）
（Reactアプリのルートフォルダに.envを作成し、使用ツールに合った環境変数名とAPI URLを設定）
npm run dev

APIへ接続する場合:

（別のターミナルで、バックエンドの説明に従ってAPIサーバーを起動）

.envの値は接続先を設定するもので、Axiosのリクエスト処理やAPIサーバーを自動で作るものではありません。
ReactコードからAxiosを呼び出し、APIサーバーが設定したURLで起動して初めて通信できます。
